############ Help
usage: wiki [-h] [--config CONFIG] COMMAND ...

Personal wiki CLI: a local harness around Gemma 4 E2B (MLX, 4-bit) and your own notes.
Everything runs on this computer; models load from the Hugging Face cache only.

Modes
  chat    personal assistant ("Sarge"). Uses the conversation; searches your notes
          only when a message needs them, and cites what it uses.
  ask     neutral, standalone research answer. Retrieves original sources, answers only
          from them with [n] citations, or says "Insufficient evidence". Ignores chat.
  search  retrieval only: prints matching original passages with paths and line numbers.
          Does not load the language model.

Maintenance
  ingest  read sources in vault/raw/, have Gemma draft linked notes in vault/wiki/,
          update vault/index.md and the Source Catalog, rebuild the index.
  index   rebuild the retrieval index (after editing notes by hand).
  check   verify filenames, headings, links, source references and raw file hashes.

positional arguments:
  COMMAND
    ingest         build or update wiki notes from sources
    index          rebuild navigation pages and the retrieval index (no model)
    search         show matching original passages (no model)
    ask            cited answer from original sources
    chat           personal assistant with conversation context
    check          validate the vault: names, links, sources, hashes
    help           show this help

options:
  -h, --help       show this help message and exit
  --config CONFIG  path to config.toml (default: next to the launcher)

Required inputs
  .venv with requirements.txt        scripts/setup.sh (needs internet once)
  models in the Hugging Face cache   mlx-community/gemma-4-e2b-it-4bit,
                                     mlx-community/embeddinggemma-300m-8bit
  sources in vault/raw/              .md, .txt or .json, kept unchanged
  retrieval index in data/index/     built by `ingest` or `index`

Configuration
  config.toml         paths, model ids, chunk sizes, k, temperatures, project names
  prompts/persona.md  chat voice and capabilities (chat only)
  prompts/wiki-instructions.md  research rules (ask only)

Examples
  ./wiki ingest ./vault/raw

Asked for: How the networking tracker prevents one user from reading another user's contacts
Relevant facts:
* A request may touch a row only when `auth.user_id() = contacts.user_id` [1].
* The `UPDATE` policy prevents a user from editing another user's contact or reassigning one of
    their own contacts to another user [1].
* Having both `USING` and `WITH CHECK` in the `UPDATE` policy means a user can neither edit someone
    else's contact nor re-assign one of their own contacts to another user [1].
* The `UPDATE` policy requires that the row after the update still satisfy `auth.user_id() =
    user_id` if it is to be allowed [1].

check · is the thing asked for in these facts? Gemma: 'YES' → YES

── step 2 · answer ─────────────────────────────────────────────
Answer: The networking tracker prevents one user from reading another user's contacts because a
    request may only touch a row when `auth.user_id() = contacts.user_id` [1]. The `UPDATE` policy,
    which uses both `USING` and `WITH CHECK`, ensures that a user cannot edit another user's contact
    or reassign one of their own contacts to another user [1]. This policy requires that the row
    after an update still satisfy `auth.user_id() = user_id`, which can only be true if the row
    still belongs to the user [1].

    │ ### Why the API proxies instead of connecting to Postgres directly
    │ 
    │ A conventional backend holds a privileged connection string and writes `WHERE user_id = $1` in every
    │ query. One forgotten clause and a user sees someone else's data.
    │ 
    │ This API holds no privileged credential at all. It passes the caller's own token through to the Data
    │ API, so Postgres evaluates the RLS policies for that specific user on every statement. Ownership is
    │ not something the application code has to remember — it is a property of the database. The cost is
    │ one extra network hop per request, which is a trade I would make again for this kind of data.
